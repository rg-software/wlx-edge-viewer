## Why

The plugin currently runs only on Windows inside Total Commander via WebView2. Double Commander uses the same WLX contract on Linux, but there is no Linux build and no engine that can target it. We want a workable Double Commander Lister on Linux without forking the source tree, and we are willing to simplify the Windows tree (drop underused features, encapsulate platform specifics) to get there cleanly.

## What Changes

- **New**: Linux build via CMake + Qt6 (Qt Web Engine), producing `EdgeViewer.wlx64` loadable by Double Commander.
- **New**: `IWebView` abstract interface in shared code; processors stop taking `wil::com_ptr<ICoreWebView2>` and stop including `<wil/com.h>`/`<webview2.h>`. Two concrete backends (`WebView2Backend` for Windows, `QtWebEngineBackend` for Linux) live in platform-only `.cpp` files.
- **New**: Platform helpers split by file (`Platform_Win.cpp` / `Platform_Linux.cpp`), not by `#ifdef` inside shared files. `Globals.h` no longer pulls in `windows.h`, `wil`, or `webview2.h`.
- **New**: `EdgeLister` split per platform. The Linux side uses a `QWidget*` parent directly (no `RegisterClassA`/`WNDPROC`/`WM_COPYDATA` IPC).
- **Modified**: `edgeviewer.ini` `[Chromium]` section renamed to `[WebView]`; Chromium-specific keys (`Switches`, `BrowserExecutableX64Folder`, etc.) are dropped on both platforms. `UserDir` is retained semantically (per-engine profile directory).
- **BREAKING** (config): the `[Chromium]` section no longer exists; users with custom `Switches`/`BrowserExecutableX86Folder`/`BrowserExecutableX64Folder` keys must migrate to `[WebView]` (only `UserDir` is honored).
- **Removed** (both platforms, future-work): HTML per-file encoding override (`[HTML] DetectEncoding=1` path in `HtmlProcessor` + the `gs_Htmls` map + the `WebResourceRequested` interceptor in `WebView2.cpp`). Modern HTML self-describes charset via BOM or `<meta charset>`; both engines sniff when absent. The feature can be reintroduced as a separate change if real-world need appears. **Known limitation:** an HTML file with no BOM, no `<meta charset>` declaration, and a non-UTF-8 encoding (e.g. Windows-1251, KOI8-R, GBK) will be mis-rendered by the engine's sniffing fallback. Re-introduction trigger: at least one reproducible user report with a sample file. Re-introduction design constraint: must work cross-platform on both WebView2 (Windows) and Qt Web Engine (Linux) — the previous `WebResourceRequested`-based approach was Windows-only and would need to be redesigned for Linux (e.g. a `QWebEngineUrlRequestInterceptor` in `QtWebEngineBackend` plus a unified `IWebView::OverrideEncoding` method that `QtWebEngineBackend` wires to `QWebEnginePage`).
- **Future-work (Linux only)**: native shell right-click context menu inside the Lister; dynamic directory thumbnails (GDI+ + `IShellItemImageFactory` path in `DirProcessor`); per-processor sticky zoom hot-key handling. These continue to work on Windows and are simply not implemented on Linux in this change.
- **Refactor (Windows only)**: simplify `WM_COPYDATA` IPC between WLX callbacks and the WebView, if the early spike confirms it is safe. If the spike fails, the existing mechanism is preserved unchanged inside `EdgeLister_Win.cpp`.

## Capabilities

### New Capabilities

- `linux-runtime`: the plugin builds on Linux and runs inside Double Commander. Specifies which file types render on Linux, the build artifact (`EdgeViewer.wlx64`) and how it is packaged, the configuration layout of `[WebView]` on Linux, and the deferred (future-work) behaviors that work on Windows but are not implemented on Linux in this change.

### Modified Capabilities

(This section amended after `characterize-existing-behavior` archived baseline specs to master. Every modification below is a delta against the corresponding `openspec/specs/<capability>/spec.md`.)

- `html`: HTML charset override (`[HTML] DetectEncoding` path, the `gs_Htmls` map, and the `WebResourceRequested` interceptor) is REMOVED on both platforms. Modern HTML self-describes charset via BOM or `<meta charset>`; both engines sniff when absent. The BOM detection and meta-charset detection helpers (`HtmlProcessor::detectedFromBom/Meta/Charset`) are also removed as dead code; they have tier-1 tests today that will be deleted alongside.
- `directory-view`: dynamic shell thumbnail generation (`DirProcessor::genDirThumbnail` with `IShellItemImageFactory` + GDI+ + base64) stays on Windows but is deferred as future-work on Linux; the Linux build always uses the static `folder.png` / `file.png` icons from `Resources/assets/dirviewer/`. The `GenDirThumbs` ini key is ignored on Linux if set.
- `popup-context-menu`: the native shell right-click menu (`EdgeLister::showPopupMenu` via `IShellFolder` / `IContextMenu` / PIDL) stays on Windows and is not implemented on Linux in this change; right-clicking inside the rendered view on Linux produces no plugin-specific popup.
- `plugin-config`: `[Chromium]` section renamed to `[WebView]` on both platforms. Chromium-specific keys (`Switches`, `BrowserExecutableX86Folder`, `BrowserExecutableX64Folder`, `CleanupOnExit`) are dropped from the spec; only `UserDir` is retained semantically as the per-engine profile directory. The `[HTML] DetectEncoding` key is removed from the spec since the override mechanism is removed entirely.
- `wlx-contract`: the Windows export set (the 12 functions in `EdgeViewer.def`) stays unchanged. The Linux export set is the same names exported via CMake visibility settings instead of a `.def` file. `BuildDetectString` (already extracted to `EdgeViewer/WlxDetect.{h,cpp}` and tested in tier4) is reused unchanged on both platforms — the detect-string format is identical.
- `zoom-control`: the per-processor `KeepZoom` persistence (`gs_ZoomFactor` map populated via `ZoomFactorChanged` events) stays on Windows but is not implemented on Linux in this change. `ZoomHotkeyHandled` (already extracted to `EdgeViewer/ZoomHotkey.{h,cpp}` and tested in tier4) is reused unchanged on both platforms; the Linux backend may choose to wire it to Qt Web Engine's `QWebEngineView` zoom controls or skip the discrete-step table per the future-work note.
- `accelerator-keys`: the WebView2 accelerator-key relaying (`AddAcceleratorKeyHandler`, JS `KeyQ` / `Digit1..8` bridge, `WM_WEBVIEW_KEYDOWN` / `WM_WEBVIEW_JS_KEYDOWN` posting to parent) stays unchanged on Windows and is not implemented on Linux in this change. The Linux backend defers to Qt Web Engine's and Double Commander's own focus management.
- `text-search` and `print`: `BuildFindScript` and `BuildPrintScript` (already extracted to `Navigator.{h,cpp}` as free functions and tested in tier4) are reused unchanged on both platforms — only the `ExecuteScript` call behind the interface differs between `WebView2Backend` and `QtWebEngineBackend`. No spec-level behavior change.
- `dark-mode`: the `gs_IsDarkMode` flag still drives `CSS`/`CSSDark` selection in the processors on both platforms. The Windows `SetColorProfile` (WebView2 `PreferredColorScheme`) is not replicated on Linux; the spec's "Web engine color scheme" requirement is modified to require only that the processors inject the right CSS based on `gs_IsDarkMode` (engine-level dark scheme becomes Windows-only future-work, restored via `prefers-color-scheme` media query when Qt Web Engine is told about the dark palette).
- `test-harness`: the test harness (Catch2 v3 + `EdgeViewer.Tests`) is reused by the port. The port adds a tier 5 — mock-`IWebView` processor body tests — as the first refactor task in the implementation, per the test-harness spec's "T5 deferred to port" requirement.
- `virtual-host-mapping`, `temp-file-management`, `eml`, `markdown`, `asciidoc`, `rst`, `mhtml`, `url-files`, `images`, `other-fallback`: no spec-level behavior change on Windows; on Linux they inherit the cross-platform rendering requirement from the new `linux-runtime` spec (the `Resources/assets/*` JS/CSS bundles load and render identically via either `WebView2Backend` or `QtWebEngineBackend`).

## Impact

- **Code**:
  - New shared: `IWebView.h`, `Platform.h`.
  - New per-platform files: `Platform_Win.cpp`, `Platform_Linux.cpp`, `WebView/WebView2Backend.{h,cpp}`, `WebView/QtWebEngineBackend.{h,cpp}`, `WebView/WebViewFactory.cpp` (Windows-only, `#ifdef _WIN32`-guarded), `EdgeLister_Win.cpp`, `EdgeLister_Linux.cpp`, `CMakeLists.txt`, `Processors/DirProcessor_Win.cpp` (Windows-only thumbnail path).
  - Refactored shared: `Globals.{h,cpp}` (Win-only headers moved out), `ProcessorInterface.{h,cpp}` (`mapDomains` becomes a virtual on `IWebView`), all `Processors/*.cpp` (parameter type `wil::com_ptr<ICoreWebView2>` → `IWebView&`), `Navigator.{h,cpp}` (operates on `IWebView&`), `DllMain.cpp` (WLX callbacks call `WebViewFactory` + direct `Navigator` invocations instead of `WM_copyDATA` where possible), `HtmlProcessor.cpp` (drop `gs_Htmls`/`DetectEncoding` path), `WebView2.cpp` absorbed into `WebView/WebView2Backend.cpp` minus encoding-override plumbing.
  - `EdgeViewer/EdgeLister.{h,cpp}` → split per platform.
  - `Resources/assets/*` (JS/CSS) untouched.
- **Build**: MSBuild `.vcxproj` keeps being the Windows build; new `CMakeLists.txt` is the Linux build. `vcpkg.json` unaffected (Linux uses system Qt6 via `find_package(Qt6 ...)`; no vcpkg equivalent). The `.def` file stays Windows-only; Linux exports go through a GNU ld version script (`EdgeViewer.version`) declaring the 12 WLX symbols `extern "C"` in `DllMain.cpp` (no CMake visibility presets — hidden-visibility symbols are not exported by GNU ld even when listed in a version script, see Decision 11).
- **Dependencies**: Linux adds Qt6 (Qt6Widgets, Qt6WebEngineWidgets), `pkg-config`, `cmake`. No vcpkg change. Windows deps unchanged.
- **Config**: `edgeviewer.ini` `[Chromium]` → `[WebView]`; dropped keys are silently ignored (mINI ignores unknown keys).
- **Systems**: Windows Total Commander behavior is preserved except for the removed HTML encoding-override feature (off by default in the shipped ini) and any `WM_COPYDATA` simplification the spike approves. Linux Double Commander gains a working Lister for Markdown, AsciiDoc, RST, HTML, MHT, EML, URL, images, directories (static icons), and the generic "Other" viewer.
