## 2. Implement the primary fix (strip `Qt::Window` on the Ctrl+Q path)

- [x] 2.1a **Heuristic correction (commit `8a3102c`)** — the original heuristic `parent->parentWidget() != nullptr && (parent->windowFlags() & Qt::Window) != 0` evaluated to false on Ctrl+Q because `parent` is the central widget of the reparented `QMainWindow` form (returned by `WlxPrepareContainer` via `TQtMainWindow.GetContainerWidget → FCentralWidget`), not the form itself. Central widgets do not carry `Qt::Window`. The corrected heuristic walks one step up to the form (`parent->parentWidget()`) and uses the form's `parentWidget()` to discriminate: `const bool isQuickView = formWidget && (formWidget->parentWidget() != nullptr);`. On F3 the form is a genuine top-level (its `parentWidget()` is null), so `isQuickView` is false. On Ctrl+Q the form has been reparented into the panel (its `parentWidget()` is non-null), so `isQuickView` is true. With this correction the strip does fire on Ctrl+Q.
- [x] 2.1b **Strip target correction** — strip `Qt::Window` on the **form** (the reparented `QMainWindow`), not on the central widget, because the central widget never had `Qt::Window` in the first place. `formWidget->setWindowFlags(formWidget->windowFlags() & ~Qt::Window); formWidget->show();`.
- [x] 2.2 The strip-and-show logic runs only when `isQuickView` is true. The container-creation code (`new QWidget(parent)` + `QVBoxLayout` + `addWidget(view)` + `setFocusProxy` + `container->show()`) is unchanged after that point.
- [x] 2.3 When `isQuickView` is false (F3 case), no change is made to the parent's flags — the existing code path runs untouched. Confirmed by code review of the diff: the F3 branch is byte-identical to before (only the debug-log block and the corrected heuristic computation sit ahead of the unchanged `new LinuxBackend()` instantiation).
- [x] 2.4 The file's top-of-file comment block now describes the corrected heuristic and the strip target.
