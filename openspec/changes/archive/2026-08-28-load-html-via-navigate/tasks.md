A real `Navigate()` to that temp URL resolves document-relative subresources (`<img src="images/blue.png">`) against the **temp** folder (missing). **Approach: stop relocating and serve the forced file as `text/html` at its real location** (Linux `ev://` default-MIME parity). Removed in `Platform_Win.cpp` `GetPhysicalPath` the ForcedHtmlExt temp-copy branch (keep the UNC branch); `.xml`/`.xhtml` now resolve to their original path like genuine `.html`, so relative refs hit the source dir and auto-detect/encoding keep working. Because WebView2's `local.example` virtual host serves `.xml` as `application/xml` and bypasses `WebResourceRequested`, the Windows backend adds a custom URI scheme (Linux-parity) whose requests DO hit a `WebResourceRequested` handler that serves the mapped file with `Content-Type: text/html`; `HtmlProcessor::OpenIn` navigates ForcedHtmlExt through that scheme (`evh://local.example/<rel>`), genuine `.html` keeps `http://local.example`. (An earlier embedded-render/`<base href>` attempt was reverted — it caused an auto-detect regression and left relative images broken; an earlier JS base-injection attempt in the backends was reverted as unreliable.)
